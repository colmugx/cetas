title: Sessions

---

Cetas keeps session data under the shared Cetas durable-state root, in `sessions/`. Session JSONL transcripts and their companion metadata live there.

The automation host supports explicit same-host resume: each fresh invocation creates a session id and reports it on stderr, and a later invocation can pass `--session <id>` to continue it.

The terminal and ACP hosts use the same session storage, but the repository does **not** claim that an arbitrary conversation can already move seamlessly between hosts. Treat cross-host session resume as planned behavior until source and tests establish it as a supported contract.
