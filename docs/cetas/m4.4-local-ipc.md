# M4.4 — local single-owner IPC

Status: experimental architecture contract. M4.4a and M4.4b introduced a native lease and initial Unix IPC framing; the host client proxy and Windows named-pipe transport are not yet implemented. Normal Cetas startup does not require IPC.

## Problem statement

M4.3 gives one runtime process a per-Session event cursor and a recoverable snapshot/replay boundary. It does not make two independently started Cetas processes share that runtime. Today the Go Harness is deliberately process-single-use and embeds one `ConsoleRuntime` on a locked OS thread; the Web server composes its own `ConsoleRuntime`; and cetas-js owns a process-lifetime `CetasApplication`/Agent. Sharing `~/.cetas` therefore shares durable settings and transcripts, not a live Agent, executor, in-memory Session state, or event stream.

M4.4 must add a local process boundary without creating a second execution authority.

## Goal

For one user home and one compatible runtime protocol, exactly one process owns the live runtime. Other Cetas processes attach as Surfaces and proxy commands, approvals, and events to that owner. Only the owner may compose Agents, execute tools, mutate Session state, or append to Session journals.

The first implementation must be explicit about host compatibility. A host that cannot speak the owner's negotiated runtime protocol must fail with an actionable incompatibility error; it must not silently compose a second runtime against the same home.

## Non-negotiable invariants

1. **One owner, one executor, one journal writer.** A client never constructs an Agent or opens a writable SessionStore for a Session owned by another process.
2. **Owner lifetime is an OS-enforced lease.** A PID file, heartbeat, timestamp, or process-name check is diagnostic only and never proves ownership. The lease is acquired before runtime composition and held until runtime shutdown and transport closure complete.
3. **No split brain on stale endpoints.** Stale Unix socket cleanup and owner election must be serialized. Never unlink an endpoint merely because one connection attempt failed; re-check ownership and endpoint identity under the election primitive.
4. **Fail closed.** If ownership cannot be proved, the endpoint is ambiguous, or the protocol is incompatible, do not start a second writer.
5. **Local-only transport.** Unix domain sockets on Unix; Windows named pipes on Windows. No loopback TCP fallback and no cloud/Malphite dependency.
6. **Same-user access only.** Unix runtime directory is private (0700) and socket/lock files are owner-only (0600); verify peer credentials where supported. Windows pipe ACLs must restrict access to the current user/logon SID. A random bearer token may add defense in depth but does not replace OS ACLs.
7. **Owner-side authorization.** Tool permissions, approvals, workspace policy, cancellation, and resource budgets are evaluated by the owner. A client Surface cannot elevate the owner's policy.
8. **Per-Surface isolation.** Each connection has its own Surface identity and workspace/Session attachment. Attaching or switching one Surface never mutates another Surface's selection.
9. **Bounded transport.** Requests, event queues, and frame sizes are bounded. Backpressure is explicit; event loss is never silent.
10. **No unsafe retries.** Every request has a connection-scoped request ID and a stable operation/idempotency key where mutation semantics require it. If the connection dies after a mutation may have been accepted, the client reports an indeterminate outcome and reconciles by reading owner state. It never blindly replays the mutation.
11. **M4.3 recovery remains authoritative.** On reconnect, the client re-handshakes, re-attaches its Surface, obtains a snapshot/high-water cursor, then resumes events/replay. Runtime epoch changes invalidate old cursors.
12. **Malphite remains optional and remote-only.** M4.4 works offline and does not introduce device pairing, remote discovery, or network relay.

## Ownership and startup state machine

The startup path is a state machine, not "try connect, then start anyway":

```text
START
  |
  v
Acquire per-user OS owner lease
  | acquired
  v
Create private local endpoint
  |
  v
Compose exactly one runtime + its single journal writer
  |
  v
Serve authenticated local Surfaces
  |
  v
Stop admission -> settle/cancel owned work -> close runtime
  |
  v
Close endpoint -> release owner lease -> EXIT

If lease is already held:
  connect to its endpoint -> authenticate peer -> protocol hello
  -> attach as client (never compose a local runtime)

If lease is held but endpoint is not ready:
  wait only within a bounded startup deadline, then report owner-starting/unavailable.
  Never steal the lease or compose a competing runtime.

If lease is free but a stale endpoint remains:
  acquire the election primitive, verify stale endpoint identity,
  remove only the verified stale endpoint, then bind and publish.
```

The owner lease must be a kernel-managed lock/claim whose lifetime is tied to an open handle or bound endpoint. The implementation must prove equivalent exclusion on Unix and Windows. Do not implement this with a `pid` + `kill(pid, 0)` heuristic. Metadata such as PID, executable, protocol, runtime epoch, and start time may be published for diagnostics only.

## Local wire contract

Use a versioned, newline-delimited UTF-8 JSON envelope initially. The transport is a byte stream; the protocol owns framing, validation, limits, and correlation.

### Handshake

Client sends:

```json
{
  "type": "hello",
  "protocol": "cetas.local/1",
  "host": "cetas-go",
  "host_version": "…",
  "capabilities": ["surface.attach", "event.cursor.v1"],
  "client_instance_id": "…"
}
```

Owner replies with `welcome` or a typed refusal. The welcome includes protocol version, owner process instance ID, runtime epoch, negotiated capabilities, and the maximum frame size. A client must reject an unsupported major version or a missing required capability before sending commands.

### Request, response, and event

- `request`: `request_id`, `operation_id` (for mutation reconciliation), `surface_id`, `command`, `args`.
- `response`: matching `request_id`, typed `ok`/error result, and an explicit accepted/settled distinction for asynchronous operations.
- `event`: owner EventHub frame plus the destination Surface/subscription identity. Preserve the existing `runtime_epoch`, `session_id`, `cursor`, and `cursor_advance` fields unchanged.
- `ping`/`pong`: liveness only; never use heartbeat expiry alone to steal a live OS lease.
- `goodbye`: client Surface detach; owner shutdown is a separate owner-only lifecycle operation.

The first protocol version must reuse the existing command and event payloads wherever possible. It must not invent a second Session model or duplicate transcript serialization.

### Limits and ordering

- Set an explicit maximum frame size and bounded per-client outbound queue; initially align the limit with the existing native Harness transport (4 MiB) unless tests justify a smaller value.
- Preserve per-Surface command ordering. Independent Surfaces may make concurrent requests; the owner serializes mutations through the existing runtime/Agent admission rules.
- When a client queue fills, disconnect or mark that Surface as requiring resnapshot. Never drop an event and continue as if the stream were complete.
- Event fanout is per subscription. A unicast response/control frame must not advance the Session broadcast cursor.

## Host adapter boundary

The owner is the process that actually composes the runtime. The IPC server must sit at the host/runtime boundary and proxy the existing command/event API; it must not sit below the journal and create a second persistence path.

Before enabling a host pair, document and test its adapter mapping:

| Surface | Required adapter behavior |
| --- | --- |
| Go → Go | Go Harness client proxies Request/Events to the elected ConsoleRuntime owner |
| Web → Web | WebSocket Surface attaches to the owner rather than composing another ConsoleRuntime |
| JS → JS | secondary JS host proxies CetasApplication operations to the elected JS owner |
| Go ↔ JS | both sides negotiate one common command/event contract; unsupported capabilities are refused, not emulated by a second Agent |

The existing Go Harness process-local `activated` guard remains useful inside one process but is not a cross-process ownership mechanism. The existing Cetas-JS `CetasApplication` operation coordinator remains the in-process admission authority; IPC must route through it rather than bypass it.

## Failure and recovery semantics

- Owner process exit releases the OS lease. Existing clients observe transport closure and enter a disconnected state.
- A client does not assume an operation failed merely because its response was not received. It queries operation/session state after reconnect using the stable operation ID.
- No in-flight Agent turn is automatically resumed by a replacement process. The new owner composes from durable state, reports interrupted work, and requires the existing explicit recovery policy.
- A new owner receives a new runtime epoch. Clients discard old in-memory cursors and establish a fresh snapshot baseline before accepting broadcasts.
- Owner shutdown first withdraws new admissions, then settles/cancels owned work, closes runtime resources and journals, closes the endpoint, and only then releases the lease.

## Delivery slices

### M4.4a — ownership and protocol foundation

- Define the shared envelope, handshake, capability negotiation, typed refusal and frame limits.
- Implement and test a kernel-enforced owner lease for Unix and Windows, including simultaneous startup and owner-crash release.
- Publish owner metadata only after the lease is held; remove it only while still holding the lease.
- Add tests proving that a second process cannot compose a second runtime when an owner exists.

### M4.4b — owner transport

- Add Unix domain socket and Windows named-pipe listeners.
- Authenticate same-user clients, bind each to an independent Surface, and proxy request/response/event frames.
- Add bounded queues, deadlines, disconnect cleanup and observable backpressure.

### M4.4c — host adapters

- Route Go Harness requests and events through the owner transport.
- Route Web/JS Surfaces through the same owner contract; preserve their existing in-process coordinators as the owner-side policy boundary.
- Refuse host pairs whose required capabilities are not negotiated.

### M4.4d — recovery and acceptance

- Reconnect with bounded backoff, re-attach, snapshot, and resume from the M4.3 cursor contract.
- Test owner crash during idle, during a turn, during an approval, and after mutation acceptance but before response.
- Acceptance matrix: JS+JS, Go+Go, Go+JS, multiple Web Surfaces, Unix and Windows.
- Assert exactly one Agent composition and exactly one journal writer for each owned Session.

## Explicitly out of scope

- Remote networking, cloud discovery, device pairing, relay, or Malphite.
- Cross-user access or multi-tenant local daemons.
- Automatic takeover/resume of an interrupted Agent turn.
- Replacing the JS-owned execution model with Go-owned execution.
- Peer-to-peer Agent messaging and delegation (M7 / Issue #154).

## Native compatibility mode (until M4.4 host integration)

**Normal startup is independent of IPC.** The Go Harness does not acquire a cross-process
owner lease by default. The in-process `ErrAlreadyStarted` guarantee is unchanged.
A separate Unix socket, Windows named pipe, or daemon is not required to use Cetas.

To explicitly exercise the experimental lease, set `CETAS_IPC_OWNER=1` on the native
Go process. With this opt-in enabled, ownership conflicts or invalid lease paths
remain fatal to that **opted-in** startup: bypassing a known owner while claiming
single-writer guarantees would be unsafe. Unset the variable to return to
ordinary standalone mode.

**Important limitation:** standalone sessions are independent processes. They
must not be assumed to share live Session state or safely write the same Session
journal concurrently. The default is a compatibility measure while the IPC
owner/client proxy remains unfinished, **not** an end-to-end single-writer proof.

## M4.4b incremental owner health endpoint

With `CETAS_IPC_OWNER=1`, a successfully booted native Go Owner now opens
a local Unix endpoint *after* the real ConsoleRuntime announces its runtime
epoch. It offers only the `health.ping` capability: versioned hello/welcome,
correlated ping/pong, bounded peers and frames, and typed refusal of every
request or event command. No Agent execution, transcript, credentials, or
Session data are exposed. `ProbeLocal` can check the endpoint without
creating runtime state. The listener and peers close before releasing the
kernel owner lease. Endpoint or transport failures produce diagnostics but
cannot bring down a healthy Agent.

Default Cetas startup still does not acquire the lease or create IPC sockets.
On Windows, the named-pipe endpoint remains unimplemented; opting into the
lease does not turn that into a TCP server. This is *not* yet multi-process
Session collaboration: command/event dispatch, per-Surface authorization,
peer credential checks, and secure Windows named-pipe ACLs remain unimplemented.
