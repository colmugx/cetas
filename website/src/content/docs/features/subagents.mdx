## 评审的人，改不了代码

让 agent 自己评审自己的改动，有个绕不开的问题：它拿着你全部的工具，"只报告别修改"全靠口头嘱咐。子代理把这句话变成配置。

在项目的 `.cetas/agents/` 下建一个 `reviewer.md`：

```markdown
---
name: reviewer
description: 只读的 diff 评审员
tools: read, grep, glob
mode: readonly
---

你评审改动，不动工作区。
```

三个属性定义一个只读评审员：它看不见 `write`，跑不了 `bash`。父会话开 `yolo` 也一样，子代理的档位是它自己的。

## 一次调研，不占主窗口的上下文

"把 auth、billing、jobs 三个模块的鉴权流程摸清楚"。普通做法是读六十个文件，窗口里堆满中间过程，最后 `/compact` 三次。

交给子代理，三个子会话同时读，主窗口只收到三份摘要。那六十个文件的内容从来没进过你的上下文，也就不产生这部分开销。

## 三行定义，就能用

- 放 `<CETAS_HOME>/.cetas/agents/` 全机器可用，放项目的 `.cetas/agents/` 跟仓库走。
- `tools` 不写就继承默认；写 `[]` 一个工具都没有；写列表就是列表。
- 并发和总量有默认值（一波 16 个、并发 4、每会话 64 次），写在 `subagent.limits` 里可以调。跑偏的计划到第 64 个会被拦下。

使用时没有任何特殊命令，直接说事："用 reviewer 评审我未提交的改动，只报问题。"它需要你拍板时会停下来问，答案回到同一个会话。
