这一页不逐个对比具体产品，只讲四条结构性的差异。它们好验证：装好后每一条都能亲手确认。

## 活有出处，交接有底

Board 把一句需求变成一张任务图：依赖没齐的任务不动，跑完的停在验收门口。每条任务留下 diff、测试证据和来龙去脉，记录在本地，你的 agent 自己也查得到。第二天开板接着跑，任务还在原地，这些记录本身就是交接文档。见[Board](/features/board/)。

## 边界是配置，不是嘱咐

子代理的工具面和权限档位写在它的定义文件里：三个属性就是一个只读评审员，父会话开 `yolo` 也改变不了它的档位。权限的五种姿态由你逐会话决定，从 `readonly` 到 `yolo`；计划模式在批准之前一个字节都写不进去。见[子代理](/features/subagents/)与[权限](/configuration/permissions/)。

## 上下文的账单，算法不同

调研交给子代理，主窗口只收摘要；循环和过滤交给沙箱里的小程序，中间结果从头到尾没进过上下文。同样一批活，上下文的开销完全不同。见[子代理](/features/subagents/)与[Bunraku](/features/bunraku/)。

## 文档的默认形态是机器可读

全站 `llms.txt` 与 `llms-full.txt`，每个文档页带 `.md` 源文件。让另一个 agent 先读完文档再决定装不装，是受支持的使用方式。见 [/llms.txt](/llms.txt)。

## 什么时候值得换，什么时候先别换

**值得换**：你要知道它干过的活从哪查；你要评审的人真的改不了代码；你在意上下文的账单；你有脚本化、CI 场景——`cetas-run` 一次进程一个回合，成败由退出码说话。

**先别换** —— 下面这些现在没有：

- `/sessions` 只列当前项目的会话，没有跨项目视图；跨入口续接是计划中的行为，今天别依赖；
- 没有图形界面，终端是第一入口；
- 没有团队协作功能：没有共享会话、组织管理、集中权限，每份状态都在各自的机器上；
- 不替你管供应商账号，模型自己注册、自己接；
- 它明说自己在实验期：npm 那份最稳，锁版本、读[更新日志](/changelog/)、有节奏地升。

想看更底层的论述（这个内核为什么靠得住），见[简介](/introduction/)的「为什么是 Posoco」一节。
