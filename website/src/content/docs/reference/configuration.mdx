## `settings.json`

Path: `<home>/.cetas/settings.json`.

Known top-level responsibilities in the current core:

| Key | Purpose |
| --- | --- |
| `providers` | Provider-extension configuration. Provider-specific values are interpreted by the extension, not by core. |
| `model` | Persisted active router slot id, in `provider/model` form. |
| `reasoning_effort` | Optional persisted effort for the selected model. |

Cetas preserves unrelated settings keys when it updates the active model selection.

Normal startup creates a missing `.cetas/settings.json` with an empty `providers` object for the native, runner, and JS terminal hosts. Existing files (including empty or malformed JSON) are never overwritten by bootstrap; correct or back up a malformed file before retrying. The JS terminal host publishes a complete file atomically so simultaneous first starts cannot observe partial JSON.

## Other durable paths

| Path | Purpose |
| --- | --- |
| `<home>/.cetas/credentials/` | Provider credential storage |
| `<home>/.cetas/model_lists.json` | Discovered model catalogs, one record array per provider |
| `<home>/.cetas/mcp.json` | User-level MCP server configuration |
| `<home>/.cetas/sessions/` | Session transcripts and companions |
| `<home>/.cetas/debug/` | Debug taps — `<session-id>-wire.jsonl`, `<session-id>-catalog.json` |
| `<cwd>/.mcp.json` | Project-local MCP configuration, overriding the user-level file for matching server names |
