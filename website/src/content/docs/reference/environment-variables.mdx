| 变量 | 作用域 | 行为 |
| --- | --- | --- |
| `CETAS_HOME` | 编辑器、自动化 | 覆盖平台用户 home —— 是 `.cetas` 的**父目录**，不是目录本身。终端入口不读它。 |
| `CETAS_PERMISSION_MODE` | 编辑器（ACP） | 启动姿态：`readonly`、`workspace_write`、`interactive`、`auto`、`yolo`。不设是 `yolo`。取值不认识会警告一次并退回 `workspace_write`，所以笔误不会放宽姿态。 |
| `CETAS_MCP_MODE` | 编辑器（ACP） | `eager` 表示启动时就连接配置好的 MCP 服务器，而不是等到第一个回合。 |
| `CETAS_DELEGATE_FS` | 编辑器（ACP） | `host` 表示面向工具的文件读写走编辑器的 `fs/*` 反向调用，而不是本地文件系统。取值不认识会警告并保持 `local`。 |
| `CETAS_DEBUG_WIRE` | 编辑器（ACP） | `1` 时把这个会话的线上流量追加到 `<CETAS_HOME>/.cetas/debug/<session-id>-wire.jsonl`。 |
| `CETAS_DEBUG_MCP_CATALOG` | 编辑器（ACP） | `1` 时把这个会话的工具目录 dump 到 `<CETAS_HOME>/.cetas/debug/<session-id>-catalog.json`。 |
| `CETAS_REGISTRY` | 终端 | 覆盖 `/update` 用的 npm registry —— 用于内部镜像。 |
| `CETAS_MEMOH_HOME` | Memoh 运行时 | 迁移独立版本的 Memoh 运行时自己的状态目录。 |

自动化入口用命令行参数表达模型、档位、权限和无人值守行为，而不是这些变量 —— 见[自动化](/automation/)。

## 说明

- `CETAS_HOME` 不是通用的：终端入口直接解析平台 home，所以脚本里设的 `CETAS_HOME` 只影响 `cetas-acp` 和 `cetas-run`，不影响 `cetas`。见 [Cetas Home](/configuration/cetas-home/)。
- 调试开关是按会话的：首次使用时才创建 `debug/`，事前不需要清理任何东西。
- 笔误一律往安全侧失败：权限取值错了退回更窄的姿态，调试开关错了就当没开（只有 `1` 才开启）。
