The conclusion first: caveman is a serious tool — [caveman.so](https://caveman.so)
and the [GitHub repository](https://github.com/JuliusBrussee/caveman)
(Apache-2.0) are actively maintained, their own measurements found 33.2% less
input token over a full session, and another example compressed a 63-token
reply down to 20. It installs in two parts: a skill that manages output
(shorter replies) and a proxy that manages input (logs, JSON, test output
compressed before they reach the model).

cetas does not bundle it, but half of those six features have counterparts you
can find in cetas.

## What has a counterpart

**Read less (compress input).** caveman compresses logs and JSON before the
model reads them. cetas takes another road: `run_code` has the model write a
small MoonBit program in which the loops and filtering happen, and intermediate
results never enter the context at all; wide research goes to subagents, and
only the summary returns to the main session. Same goal, different mechanism —
compression is an after-the-fact patch, avoidance is subtraction at the source.

**Auto (pick a model per task).** caveman picks models and effort for you.
cetas's `/model openai pick` ranks models by measured data (IQ minus token,
cost, and time, three ledgers), and `/decision` configures a separate decision
model. The difference: pick is initiated by you, not routed automatically on
every question.

**Blocks (write a script once, reuse it).** The `source` parameter of
`run_code` accepts full `.mbtx` programs, so repeatedly used scripts don't need
rewriting each time.

**Short replies (compress output).** cetas does not ship this style, but as
shown below, you can add it yourself.

## What is missing

Automatic compression of tool output before it enters context, prompt-cache
warming during pauses, waste localisation, and web-page compression — those
four cetas does not have. One `cat` of a large log lands in the context
verbatim until the threshold is reached. If your workflow deals with such
output every day, that gap is real for you.

## Want caveman? Install it and it works

A caveman skill is just a directory with a `SKILL.md`, which the cetas skill
system accepts directly:

```sh
npx skills add JuliusBrussee/caveman
```

Install under the project's `.agents/skills/` to travel with the repository, or
under `<CETAS_HOME>/.agents/skills/` to be available machine-wide. It shows up in
`/skills`, and `/caveman` then takes effect. No adaptation on our side needed.
